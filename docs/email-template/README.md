# Email Template Builder — Easy Form Builder Documentation

> [Docs index](../README.md)

راهنمای کاربر نهایی برای قالب‌ساز ایمیل Easy Form Builder: ۱۳ نوع بلوک در چهار دسته، ۶ قالب آماده، ۵ شورت‌کد پویا (یکی اجباری)، تنظیمات سراسری فونت/رنگ با فهرست ۱۵ فونت ایمیل‌امن، نوار ابزار با واگرد ۳۰ مرحله‌ای، محدودیت ۵۰ هزار نویسه‌ای، و اینکه طراحی دقیقاً روی کدام دسته از ایمیل‌های افزونه اعمال می‌شود.

- Persian (فارسی) — [راهنمای کامل قالب‌ساز ایمیل در فرم ساز آسان](EFB-Email-Template-Builder-Complete-Guide.fa.md)
- English — [How to Use the Email Template Builder in Easy Form Builder](EFB-Email-Template-Builder-Complete-Guide.en.md)

هر دو نسخه یک محتوا را کامل پوشش می‌دهند: مسیر دسترسی (پنل ← تنظیمات ← زبانهٔ قالب ایمیل، سراسری نه per-form)، جدول کامل ۱۳ بلوک با ویژگی‌های قابل‌تنظیم هرکدام، جدول ۶ قالب آماده با تعداد بلوک دقیق، ۵ شورت‌کد پویا و مکانیزم chip برای درج امن آن‌ها، تنظیمات سراسری (پس‌زمینه/عرض/شعاع گردی/فونت/جهت/رنگ دکمه)، نوار ابزار و میانبرهای صفحه‌کلید، اعتبارسنجی سمت کلاینت و سرور هنگام ذخیره، توضیح دقیق اینکه این طراحی روی کدام ایمیل‌ها (اطلاع‌رسانی، بازیابی رمز، ثبت‌نام) اعمال می‌شود و چرا ابزار «بررسی سرور ایمیل» از آن مستثناست، رفتار دقیق حالت «هرگز باز نشده»، لایه‌های پاک‌سازی امنیتی، رفع اشکال و پرسش‌های متداول.

## مرجع فنی

| موضوع | محل پیاده‌سازی |
| --- | --- |
| رابط کاربری کشیدن-و-رهاکردن (بلوک‌ها، قالب‌ها، پنل ویژگی‌ها) | `includes/admin/assets/js/email-template-builder-efb.js` (تعریف کامل خودکفا، بدون فایل CSS جدا — استایل با `injectStyles_efb()` تزریق می‌شود) |
| محل mount شدن قالب‌ساز در زبانهٔ تنظیمات | `includes/admin/assets/js/list_form-efb.js` (بلوک `nav-emailtemplate`، فراخوانی `efbEmailBuilder.init()`) |
| اعتبارسنجی سمت کلاینت هنگام ذخیره (طول، وجود shortcode_message) | `includes/admin/assets/js/list_form-efb.js` تابع `fun_set_setting_emsFormBuilder` |
| اعتبارسنجی و پاک‌سازی سمت سرور هنگام ذخیره | `includes/admin/class-Emsfb-admin.php` متد `set_settings_Emsfb()`، شاخهٔ `key == "emailTemp"` |
| بازتولید HTML نهایی از روی داده‌های JSON بلوک (`<!-- EFBDATA:... -->`) هنگام ارسال ایمیل واقعی | `includes/class-email-handler.php` متدهای `generate_from_efbdata()` و `render_efb_block()` و خانوادهٔ `render_*_block()` |
| اعمال قالب سفارشی روی انواع محتوای ایمیل (اطلاع‌رسانی/بازیابی/ثبت‌نام) | `includes/class-email-handler.php` متد `email_template_efb()` |
| ابزار «بررسی سرور ایمیل» (مسیر کاملاً جدا، بدون استفاده از قالب سفارشی) | `includes/admin/class-Emsfb-admin.php` متدهای `check_email_server_admin()` و `start_email_tester_efb()` |
| طراحی پیش‌فرض داخلی وقتی هیچ قالب سفارشی ذخیره نشده | `includes/class-email-handler.php` متد `generate_html_email_template()` |
| مقدار پیش‌فرض تنظیمات (`emailTemp`, `emailBtnBgColor`, `emailBtnTextColor`) | `includes/class-Emsfb.php` |
| عبارات ترجمه (پیشوند `eb*` برای بلوک‌ها/قالب‌ها/رابط، بدون هیچ کلید مفقود) | `includes/functions.php` |

نکات مهم برای نگهداری آینده:

- تابع‌های `email_template_efb(s)`، `EmailTemp1Efb()`، `EmailTemp2Efb()` و `fun_add_email_template_efb()` در `list_form-efb.js` (حدود خط ۳۶۳۸ تا ۳۷۳۷) **کد مرده و غیرقابل‌دسترس** هستند — بازماندهٔ رابط کاربری قبل از قالب‌ساز کشیدن-و-رهاکردن. هیچ دکمه‌ای در HTML فعلی آن‌ها را صدا نمی‌زند. قبل از مستندسازی مجدد یا استفاده از این توابع، ابتدا با grep تأیید کنید که آیا واقعاً به رابط کاربری متصل شده‌اند یا نه.
- به همین ترتیب، شاخهٔ `if ($state == "testMailServer")` داخل `email_template_efb()` (کلاس `class-email-handler.php`) هم **کد مرده** است: هیچ‌جای پروژه `send_email_state_new()` یا `email_template_efb()` را با `state = 'testMailServer'` صدا نمی‌زند. ابزار واقعی «بررسی سرور ایمیل» که کاربر می‌بیند، از یک مسیر کاملاً جدا در `class-Emsfb-admin.php` (متد `start_email_tester_efb()`) یک پیام تشخیصی ثابت را مستقیماً با `wp_mail()` می‌فرستد و هرگز از `email_template_efb()` یا قالب سفارشی عبور نمی‌کند. رشتهٔ `'testMailServer'` که در جاوااسکریپت به AJAX ارسال می‌شود صرفاً یک برچسب هم‌نام است، نه فراخوانی همان شاخهٔ PHP.
- عبارت ترجمهٔ `ChrlimitEmail` می‌گوید «حداکثر ۱۰,۰۰۰ نویسه» ولی رفتار واقعی اجراشده (هم کلاینت `> 50000` و هم سرور `> 50001`) عدد **۵۰,۰۰۰** است. این عدد قدیمی در متن باقی مانده و با رفتار واقعی هم‌خوانی ندارد؛ اگر این متن را در پنل دیدید یا در آینده تغییرش دادید، عدد صحیح را از این دو محل کد بگیرید، نه از رشتهٔ ترجمه.
- قالب‌ساز ایمیل و قالب‌ساز رنگ کادر پاسخ (`efb_open_color_modal`) هر دو انتخابگر فونت دارند اما فهرستشان متفاوت است: کادر پاسخ فونت گوگل دانلودی و وابسته به زبان سایت دارد، قالب‌ساز ایمیل فقط ۱۵ فونت وب‌ایمن ثابت دارد و به زبان سایت وابسته نیست. این دو را در مستندسازی یکسان فرض نکنید.

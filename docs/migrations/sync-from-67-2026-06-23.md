# Sync from `67` build → `wp` (production) — 2026-06-23

This covers two pieces of work requested in the same session:

1. Fixing the "add-ons being installed" message delay on `?page=Emsfb` and `?page=Emsfb_create`, in this project (`wp`) as well as in `67`.
2. Diffing all translatable strings (`__`, `_e`, `esc_html__`, `esc_attr__`, etc. with the `easy-form-builder` text domain) under `includes/` between the `67` build and this project, and porting over what was genuinely missing.

## 1. Addon-install message delayed on page load

Same root cause as already fixed in `67`: the code printed the "please wait, add-ons are being installed" HTML and then immediately called the **synchronous, blocking** `download_all_addons_efb()` (network requests + zip download + unzip, can take many seconds per add-on) before PHP's output buffer was ever flushed to the browser. The message only became visible once the entire blocking operation finished (or failed), defeating its purpose.

**Fix applied** in both `67` and `wp`:

- `includes/functions.php`: added `flush_addon_wait_message_efb()` — ends all output buffers (`wp_ob_end_flush_all()` / fallback loop) and calls `flush()`.
- `includes/admin/class-Emsfb-panel.php` (`?page=Emsfb`): call `flush_addon_wait_message_efb()` right after printing the message and before `download_all_addons_efb()`.
- `includes/admin/class-Emsfb-create.php` (`?page=Emsfb_create`): same.

Not touched: the version-mismatch path (`setting_version_efb_update()`, called when `efb_version` differs) also calls `download_all_addons_efb()` synchronously but never prints the wait message at all. That's a separate, pre-existing gap outside what was reported — flag if you want it addressed too.

## 2. Translatable-string diff (`67/includes` vs `wp/includes`)

Extracted every `esc_html__|esc_html_e|esc_attr__|esc_attr_e|__|_e|_x|_ex|esc_attr_x|esc_html_x` call with domain `easy-form-builder` from both trees (1550 unique strings in `67`, 1748 in `wp` before this change). 10 strings existed only in `67`. Each was investigated individually — most were **not** simple missing translations, so they were handled differently:

### Ported into `wp`

| String | What it actually was | Action |
|---|---|---|
| `Easy Form Builder Security Plugin Notice:` and 4 related strings (`A security plugin that may block form submissions...`, `Plugin:`, `Version:`, `If users experience 403 errors...`) | A **full feature**: an admin notice warning that an active security plugin (Wordfence, Loginizer, Sucuri, etc.) may be blocking form submissions with 403 errors. Detection logic (`update_security_plugins_list()`, the `emsfb_update_security_plugins_list` hook, `emsfb_security_plugins` option) **already existed** in `wp` — only the notice-rendering method was missing. | Added `efb_security_plugin_notice()` to `includes/admin/class-Emsfb-admin.php` (same markup/JS as `67`, reuses the existing `logo.png` asset) and hooked it via `add_action('admin_notices', ...)` next to the existing `admin_notices_efb` hook. |
| `Please go to the Add-ons Page of Easy Form Builder plugin and install the Jalili date addons` / `...Hijri date addons` (keys `IMAddonPD` / `IMAddonAD`) | Not missing — `wp` had the **same key** with slightly older wording (singular "Add-on Page" / "addon" vs. plural). | Updated wording in `includes/functions.php` to match `67`. |
| `The Conditional Logic Addon enables dynamic...` (key `condADAddon`) | Same string, only a typographic apostrophe difference (`'` vs `’`). | Updated to match `67`'s typographic apostrophe. |

### Deliberately NOT ported

| String | Reason |
|---|---|
| `Select a form` (`includes/admin/integrate-elementor.php`) | That entire file is **dead code in `67`** — it is never `require`'d or referenced anywhere in the `67` codebase. Porting it would add an unused file with no caller. |
| `Clear All` (key `clear` in `check_error_console_efb()`, `includes/class-Emsfb-formbuilder.php`) | Not a missing translation — the two builds **diverged** on this UI. `67` has a single "Clear All" button; `wp` already implements a more granular per-item `Dismiss` / `Dismiss All` / `Dismiss %s` flow. Porting `67`'s string would mismatch `wp`'s actual JS behavior. |

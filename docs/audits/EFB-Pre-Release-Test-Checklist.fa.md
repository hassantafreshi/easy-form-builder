# چک‌لیست تست کاربر پیش از انتشار — Easy Form Builder

**نوع:** تست دستی کاربر (User Acceptance Test)
**دامنه:** همه‌ی انواع فیلد + همه‌ی مسیرهای اصلی
**قابل استفاده برای:** هر انتشار (نسخه‌محور نیست)

این فایل جایگزین چک‌لیست‌های نسخه‌ای مثل `2026-08-09-4.1.3-release-test-checklist.fa.md` نیست؛
آن‌ها تفاوت یک نسخه‌ی مشخص را می‌سنجند، این یکی مطمئن می‌شود **کل افزونه** سالم است.

> قاعده‌ی کلی: هر مورد را روی **فرم منتشرشده در سایت** تست کنید، نه فقط در پیش‌نمایش فرم‌ساز.
> چند باگ واقعی این افزونه دقیقاً از همین اختلاف بین «رندر فرم‌ساز» و «رندر سرور» آمده‌اند.

---

## ۰ — آماده‌سازی محیط

- [ ] بکاپ کامل دیتابیس و فایل‌ها
- [ ] `WP_DEBUG` و `WP_DEBUG_LOG` روشن باشد، بعد `wp-content/debug.log` را **خالی کنید**
- [ ] کنسول مرورگر (F12) در تمام طول تست باز باشد
- [ ] بررسی کنید `wp-content/mu-plugins/efb-mail-capture.php` **وجود نداشته باشد** — اگر باشد هیچ ایمیلی واقعاً ارسال نمی‌شود
- [ ] هر افزونه‌ی کش صفحه را برای صفحات فرم غیرفعال یا استثنا کنید
- [ ] یک مرورگر با کاربر لاگین‌شده و یک پنجره‌ی ناشناس (بازدیدکننده‌ی مهمان) آماده کنید

**سه سایت اگر ممکن است:** نصب تازه / آپدیت روی نسخه‌ی قبلی / سایت با محتوای واقعی مشتری.

## ۱ — فیلدهای متنی و پایه

برای هر فیلد: مقدار درست بدهید، فرم را ثبت کنید، و مقدار را در **پنل پاسخ‌ها** و در **ایمیل** ببینید.

- [ ] `text` — متن ساده، شامل فارسی و نویسه‌های خاص (`& < > " '`)
- [ ] `textarea` — چند خط؛ شکست خط در ایمیل حفظ شود
- [ ] `email` — مقدار نامعتبر رد شود، معتبر بپذیرد
- [ ] `number` — حداقل/حداکثر رعایت شود
- [ ] `tel` / `mobile` — قالب شماره
- [ ] `url` — لینک نامعتبر رد شود
- [ ] `password` — قوانین پیچیدگی (۸ نویسه، عدد، حرف بزرگ، حرف کوچک)
- [ ] `postalcode` و `address_line`
- [ ] `color` و `range`
- [ ] `hidden` / `sample` — مقدار پیش‌فرض درست ذخیره شود

**انتظار مشترک:** فیلد اجباری خالی ⇐ پیام خطای فارسی زیر همان فیلد، و فرم ثبت نشود.

## ۲ — فیلدهای انتخابی

- [ ] `select` — انتخاب یک گزینه
- [ ] `multiselect` — چند گزینه، سقف `maxSelect` و کف `minSelect` رعایت شود
- [ ] `radio` و `checkbox`
- [ ] `imgRadio` — انتخاب تصویری
- [ ] `chlRadio` / `chlCheckBox` — گزینه با فیلد توضیح یا تعداد
- [ ] `trmCheckbox` — پذیرش قوانین؛ بدون تیک، ثبت نشود
- [ ] `switch` و `yesNo`
- [ ] `rating` — ستاره‌ها
- [ ] `pointr5` / `pointr10` — امتیاز عددی
- [ ] `r_matrix` / `table_matrix` — ماتریس سطر/ستون
- [ ] `smartcr` — کارت هوشمند

**تست محافظ (مهم):** روی یک فرم **غیرپرداختی** یک `select` و یک `multiselect` بگذارید.
**انتظار:** در Inspect، هیچ‌کدام کلاس `payefb` نداشته باشند و هیچ ستون قیمتی نمایش داده نشود.

## ۵ — پرداخت ⚠️ حساس‌ترین بخش

سه چیز باید هم‌زمان درست باشد: **مبلغ روی صفحه**، **مبلغ شارژشده**، **مبلغ داخل ایمیل**.
اگر این سه با هم نخوانند، مشتری مبلغ اشتباه پرداخت می‌کند و به ادمین ایمیل هشدار تقلب می‌رود.

### ۵-۱ ثبت قیمت روی صفحه

یک فرم پرداختی با **هر پنج نوع** بسازید و بعد از هر انتخاب، جمع کل بالای فرم را ببینید:

- [ ] `payRadio` — انتخاب گزینه ⇐ جمع کل زیاد شود
- [ ] `payCheckbox` — چند گزینه ⇐ جمع، همه را با هم داشته باشد
- [ ] `paySelect` — انتخاب پلن ⇐ جمع کل **حتماً** عوض شود (نه `$0.00`)
- [ ] `payMultiselect` — انتخاب چند مورد ⇐ کنار هر گزینه قیمتش دیده شود و جمع درست بالا برود
- [ ] `prcfld` — مبلغ دلخواه کاربر
- [ ] `ttlprc` — نمایش جمع کل

- [ ] **ترتیب را عوض کنید:** یک بار اول `paySelect` بعد `payMultiselect` بعد `payRadio`؛ بار دوم برعکس؛ بار سوم از وسط
  **انتظار:** در هر سه ترتیب، جمع کل عدد یکسان بدهد
- [ ] انتخاب را **بردارید**
  **انتظار:** قیمت از جمع کل کم شود

### ۵-۲ تطابق مبلغ با سرور

- [ ] در Network مرورگر، پاسخ `/payment/stripe/card/add` را باز کنید
  **انتظار:** مقدار `value` **دقیقاً** برابر عدد نمایش‌داده‌شده روی صفحه باشد
- [ ] صندوق ایمیل ادمین را ببینید
  **انتظار:** ایمیلی با موضوع `Warning Entry[Easy Form Builder]` **نیامده باشد** — آمدنش یعنی جمع سرور با جمع صفحه فرق دارد

### ۵-۳ تکمیل پرداخت

با کارت تست `4242 4242 4242 4242` / انقضا `12/34` / CVC `123`:

- [ ] پرداخت انجام شود و پیام موفقیت با شناسه‌ی تراکنش بیاید
- [ ] **کنسول مرورگر خطای قرمز نداشته باشد** (به‌ویژه `Cannot read properties of null`)
- [ ] بلافاصله بعد از پرداخت، فیلدهای قیمتی **قفل و غیرفعال** شوند
- [ ] فرم به‌طور خودکار ثبت شود و کد رهگیری بیاید
- [ ] در `debug.log` هیچ `Undefined array key "payid"` نباشد
- [ ] در `debug.log` هیچ `Table ... doesn't exist` نباشد

### ۵-۴ محتوای ایمیل پرداخت

- [ ] ایمیل ادمین و ایمیل مشتری هر دو برسند
- [ ] هر دو شامل: شناسه‌ی تراکنش، روش پرداخت، **مبلغ**، تاریخ
- [ ] **تک‌تک آیتم‌های انتخاب‌شده** با قیمت خودشان لیست شوند (پلن، افزودنی‌ها، گزینه‌ها)
- [ ] هیچ ردیفی **دوبار** تکرار نشده باشد
- [ ] عنوان نسخه‌ی ادمین «پیام جدید دریافت شد» باشد، نه «پیام شما دریافت شد»

### ۵-۵ درگاه‌ها

- [ ] `stripe` — پرداخت تکی (`charge`)
- [ ] `stripe` — اشتراک/دوره‌ای؛ دوره و تاریخ صورتحساب بعدی در ایمیل بیاید
- [ ] `paypal` (`AdnPAP`)
- [ ] `persiaPay` / زرین‌پال (`AdnPPF`) — به‌ویژه **بازگشت از بانک**: بعد از برگشت، مقادیر فرم سر جایشان باشند و ثبت کامل شود
- [ ] پرداخت **ناموفق/انصراف** ⇐ پیام خطای روشن، فرم ثبت نشود، مبلغ کم نشود

### ۵-۶ حالت خاموش

- [ ] یک فرم پرداختی روی سایتی که افزونه‌ی درگاه فعال نیست
  **انتظار:** پیام روشن به کاربر، نه صفحه‌ی سفید و نه خطای PHP

## ۶ — چندمرحله‌ای و منطق شرطی

- [ ] فرم چندمرحله‌ای — دکمه‌های بعدی/قبلی، نوار پیشرفت
- [ ] فیلد اجباری خالی در مرحله‌ی ۱ ⇐ اجازه‌ی رفتن به مرحله‌ی ۲ ندهد
- [ ] مقادیر مرحله‌ی قبل با برگشت حفظ شوند
- [ ] منطق شرطی (`AdnSMF`) — نمایش/مخفی کردن فیلد
- [ ] فیلد **مخفی‌شده‌ی اجباری** جلوی ثبت را نگیرد
- [ ] شرط روی فیلد قیمتی ⇐ با مخفی شدن، مبلغش از جمع کل کم شود
- [ ] اعلان شرطی — ایمیل فقط به گیرنده‌ی درست برود

## ۷ — ایمیل و اعلان‌ها

هر سه حالت را جداگانه تست کنید:

- [ ] حالت **کد رهگیری** (`traking_link`) — کد رهگیری + دکمه‌ی مشاهده‌ی پیام‌ها
- [ ] حالت **محتوا + لینک** (`msg` ⇐ `message_link`) — مقادیر فرم به‌علاوه‌ی کد رهگیری
- [ ] حالت **فقط محتوا** (`just_msg` ⇐ `just_message`) — فقط مقادیر، بدون کد رهگیری

برای هر حالت:

- [ ] ایمیل ادمین و ایمیل کاربر هر دو برسند
- [ ] **ظاهر ایمیل سالم باشد** — رنگ، فونت و دکمه‌ها اعمال شده باشند (نه یک `<div>` بی‌استایل)
- [ ] در جیمیل، اوت‌لوک و موبایل باز کنید
- [ ] فارسی راست‌چین درست نمایش داده شود
- [ ] Email Template Builder — قالب سفارشی بسازید و ببینید همان اعمال شود
- [ ] وقتی سوییچ ارسال ایمیل **خاموش** است ⇐ فرم‌ساز هشدار بدهد و ایمیلی نرود

## ۸ — کد رهگیری و باکس پاسخ

- [ ] با کد رهگیری، پیام را ببینید
- [ ] کد اشتباه ⇐ پیام خطا
- [ ] ادمین از پنل پاسخ بدهد ⇐ کاربر ببیند
- [ ] **نام پاسخ‌دهنده** روی کارت درست باشد، و بعد از رفرش صفحه **همان نام** بماند
- [ ] پاسخ همراه فایل ضمیمه
  **انتظار:** بعد از ارسال، چیپ‌های فایل پاک شوند ولی فایل روی پیام ارسال‌شده بماند
- [ ] کاربر از سمت خودش پاسخ بدهد
- [ ] در باکس پاسخ ۴ فایل ضمیمه کنید ⇐ سه‌تا مجاز، چهارمی رد

## ۱۱ — پنل مدیریت

- [ ] فرم‌ساز باز شود، **کنسول خطا ندهد**
- [ ] هر نوع فیلد را اضافه، ویرایش، جابه‌جا و حذف کنید
- [ ] پیش‌نمایش فرم‌ساز با فرم واقعی سایت یکی باشد (به‌ویژه فیلدهای پرداختی و قیمت‌ها)
- [ ] ذخیره‌ی فرم و بازکردن دوباره ⇐ همه‌ی تنظیمات سر جایشان
- [ ] لیست پاسخ‌ها — جست‌وجو، فیلتر، صفحه‌بندی، خروجی
- [ ] حذف پاسخ و حذف فرم
- [ ] تنظیمات — ذخیره و بازخوانی، بدون از دست رفتن تب‌های دیگر
- [ ] چند فرم روی **یک صفحه** ⇐ هرکدام مستقل کار کنند

- [ ] بعد از آپدیت، **افزونه‌ها پاک نشده باشند** یا مسیر بازیابی روشن باشد

# چک‌لیست انتشار Easy Form Builder 4.3.2

نتیجهٔ آزمون رگرسیون نهایی (۲۰۲۶-۱۱-۲۶) و ترتیب انتشار، برای مالک. همهٔ فرمان‌ها و مسیرها به خط لاتین و داخل backtick آمده‌اند. ترجمه‌ها خارج از این انتشار است (تصمیم ۱ مالک).

## ۱. آنچه منتشر می‌شود

فقط فایل‌هایی را بارگذاری کنید که در این بخش آمده‌اند. ساخت‌های قدیمی در `scratchpad/zips/` (و هر zip دیگری که sha256 آن با این فهرست یکی نیست) هرگز نباید بارگذاری شوند.

## ۲. ترتیب انتشار

1. **اول افزونه‌ها:** zipهای بخش ۱ و کاتالوگ را روی سرور افزونه‌ها بارگذاری کنید و پس از بارگذاری sha256 هر کدام را با جدول مقایسه کنید.
2. **حداقل نسخه فقط پس از انتشار هسته:** مقدار `v = 4.3.2` را برای افزونه‌های ستون «4.3.2» تنها وقتی تنظیم کنید که هستهٔ 4.3.2 منتشر شده باشد.
3. **افزونهٔ ویژهٔ 4.3.2 هرگز به سایت 4.3.1 داده نشود (E403):** تا پیش از انتشار هسته، سرور نباید این افزونه‌ها را به سایت‌های 4.3.1 بدهد؛ هستهٔ 4.3.1 با `v` بالاتر از نسخهٔ خودش نصب را رد می‌کند، پس `v` درست شرط ایمنی است.
4. **۲۴ ساعت پس از افزونه‌ها هسته را منتشر کنید:** محتوای `easy-form-builder-4.3.2.zip` را در `trunk` مخزن SVN وردپرس.org بگذارید و آن را به `tags/4.3.2` کپی کنید.
5. **Data Tools 1.1.0 همان روز با هسته** منتشر شود.

### ۳.۵ ارتقای 4.3.1 ← 4.3.2 روی SQLite

مراحل `tests/upgrade/run-upgrade-431.sh` (که MySQL می‌خواهد) با همان `tests/upgrade/upgrade-lib.php` روی وردپرس 7.1.5 تازه با SQLite (`scratchpad/final2/upgrade-sqlite.sh`): zip رسمی 4.3.1 (sha256 `dd6883f8…`)، ۱۰۰٬۰۰۰ پاسخ، ۲۰٬۰۰۰ پاسخ‌گویی، ۵٬۰۰۰ نشست، ۲٬۰۰۰ پرداخت قدیمی، فرم‌های Stripe / PayPal / Persia Pay، متن‌های سفارشی و کلیدها؛ سپس zip نهایی 4.3.2.

- ۲۳ از ۲۴ بررسی پاس: سطرها و checksum محتوای فرم‌ها، پاسخ‌ها، پاسخ‌گویی‌ها، نشست‌ها، پرداخت‌ها و تنظیمات بی‌تغییر (پس از به‌روزرسانی و پس از کارهای پس‌زمینه)؛ ۱۴ جدول و ستون‌های تازه؛ اجرای دوم هیچ چیز اعمال نکرد و هیچ سطری را عوض نکرد؛ به‌روزرسانی طرح‌واره ۱٫۳ ثانیه (حد ۳۰ ثانیه).
- تنها شکست «محیط» است: شش هشدار `wp_version_check()` / `wp_update_plugins()` / `wp_update_themes()` از `wp-includes/functions.php` هنگام `wp cron event run` (سایت به وردپرس.org راه ندارد). درخواست به‌روزرسانی خود ۰ خطا، هشدار یا deprecation داشت.
- قالب ایمیل پس از به‌روزرسانی نشانی همین سایت را دارد، نه `{efb_plugin_url}` (رفع ۳).
- MySQL / MariaDB با ۱۰۰ هزار پاسخ را QA-4 پیش‌تر اجرا کرده بود (۲۴/۲۴)؛ در این دسته تکرار نشد.

## ۴. کارهای باقی‌ماندهٔ مالک

- **رمز CI:** `EFB_ADDONS_TOKEN` را در تنظیمات مخزن GitHub بسازید (`.github/workflows/ci.yml` با آن مخزن افزونه‌ها را کنار هسته می‌گیرد؛ بدون آن آزمون‌های افزونه‌ها در CI اجرا نمی‌شوند).
- **سرور لایسنس، F21:** فیلد قرارداد v1 در سرور لایسنس (تا آن روز F21 ساکت می‌ماند؛ تصمیم ۴).
- **فعال‌سازی آفلاین `md5(host)`:** عمدی و مستند (حالت آفلاین fa_IR)؛ جایگزینی آن با کدهای امضاشده در قرارداد لایسنس v1.
- **صفحه‌های راهنما:** برای افزونه‌هایی که صفحه ندارند (دکمهٔ Help فعلاً پنهان است؛ تصمیم ۸) صفحه بنویسید و `help_url` را در کاتالوگ بگذارید.
- **`mismatched_plugin_name`:** هشدار Plugin Check: عنوان `readme.txt` با نام سرخط افزونه یکی نیست؛ انتخاب نام نهایی با مالک است (`docs/release/plugin-check-waivers.md`).
- **آزمون‌هایی که فقط روی XAMPP مالک ممکن است:** کلیدهای واقعی Stripe، PayPal و درگاه‌ها؛ SMS واقعی؛ ایمیل واقعی؛ Safari روی iOS؛ پوشهٔ `efb-private` روی Apache و nginx؛ LiteSpeed. نصب هر افزونه روی سایت تمیز 4.3.1 و 4.3.2 (معیار خروج سرور افزونه‌ها).
- **ترجمه‌ها:** ۴۹+ عبارت تازه ترجمه نشده است (تصمیم ۱)؛ فهرست عبارت‌ها تازه است.
- **ادغام `dev4` در `main`** در هر چهار مخزن.
- **راز reCAPTCHA بدون رمزنگاری** در ردیف تنظیمات می‌ماند (تعویق ثبت‌شده).
- **موارد P2 ساخته‌نشده:** قانون‌های منطق شرطی درون یک ردیف تکرارشونده، و فهرست B11.

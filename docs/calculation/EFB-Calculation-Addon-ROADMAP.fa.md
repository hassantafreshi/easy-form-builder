# EFB Calculation Addon - رودمپ کامل افزودنی مستقل محاسبات فرم

**Keywords / کلمات کلیدی:** Easy Form Builder calculation addon, فیلد محاسباتی وردپرس, فرمول‌ساز فرم, ماشین حساب فرم, قیمت‌گذاری پویا, calculated fields, price estimator, loan calculator, BMI, dynamic pricing, فاکتور آنلاین, برآورد هزینه, جمع خودکار.

> [فهرست مستندات](../README.md) · [Quiz Addon](../quiz/README.md) · [Conditional Logic](../conditional-logic/README.md)

## خلاصه محصول

افزودنی Calculation یک addon **کاملاً مستقل** است که به هر فرم Easy Form Builder (فرم عادی، پرداختی، چندمرحله‌ای و حتی quiz) قابلیت **فیلد محاسباتی** و **فرمول‌نویسی روی مقادیر فیلدها** اضافه می‌کند: جمع و ضرب زنده، نگاشت عدد به گزینه‌ها، توابع ریاضی و شرطی، قالب‌بندی عدد/ارز (شامل اعداد فارسی)، و محاسبه مجدد امن سمت سرور — به‌ویژه برای قیمت‌گذاری پویا در فرم‌های پرداخت.

**اصل طراحی:** این add-on به‌طور کامل در `vendor/calculation/` نوشته می‌شود، به هیچ نوع فرم خاصی گره نمی‌خورد و وابستگی اجباری به هیچ addon دیگری ندارد (اتصال به Quiz و پرداخت‌ها **اختیاری** و از طریق فیلتر است). اگر addon نصب یا فعال نباشد، هیچ فرم موجودی تغییر رفتار نمی‌دهد.

## بررسی معماری فعلی — چرا بدون تغییر ساختار ممکن است

نتیجه بررسی دقیق کد نسخه 4.0.10:

1. **الگوی addon موجود است:** بارگذاری شرطی در `Emsfb::includes()` با کلید `Adn***` (نمونه AdnSMF در `includes/class-Emsfb.php:155-162`)، نصب zip در `vendor/` از صفحه Add-ons (`includes/admin/class-Emsfb-addon.php`)، و بررسی آمادگی نوشتن در `vendor/` هنگام فعال‌سازی (`emsfb.php::emsfb_check_file_access_efb`).
2. **ساختار JSON فرم آزاد است:** فرمول‌ها و تنظیمات فیلد محاسباتی داخل `form_structer` (MEDIUMTEXT) ذخیره می‌شوند — بدون تغییر schema. مقادیر عددی گزینه‌ها (calc value) به‌عنوان کلید اضافی روی عناصر option موجود می‌نشیند.
3. **نقطه دخالت سمت سرور موجود است:** فیلتر `efb_logic_prepare_submission` در `class-Emsfb-public.php:1763` روی هر submission اجرا می‌شود؛ addon محاسبات همان‌جا مقادیر محاسباتی را **از نو سمت سرور** حساب و جایگزین مقدار کلاینت می‌کند (الگوی اثبات‌شده افزودنی Logic در `vendor/logic/class-Emsfb-logic-validator.php:915-925`).
4. **فیلد نمایشی نیاز به نوع فیلد جدید در هسته ندارد:** فیلد محاسباتی روی فیلد `text`/`html` موجود با پرچم addon-side سوار می‌شود و اسکریپت عمومی addon آن را readonly/زنده رندر می‌کند.
5. **UI ادمین تزریق‌پذیر است:** فیلتر `efb_admin_localize_vars` (`includes/admin/class-Emsfb-addon.php:156`) و `admin_enqueue_scripts` برای افزودن پنل فرمول‌ساز به builder کافی است.

### نتیجه بررسی

مثل Quiz، تنها لمس هسته از جنس پیکربندی تکراری است: کلید `AdnCLC` در دو لیست موجود + بلوک بارگذاری شرطی. **هیچ تغییر ساختاری لازم نیست.**

## نام و ساختار پیشنهادی Addon

**نام محصول:** EFB Calculation & Dynamic Pricing Addon
**کلید addon پیشنهادی:** `AdnCLC` (بدون تداخل با کلیدهای موجود)
**مسیر اصلی:** `vendor/calculation/`
**کلاس اصلی:** `\Emsfb\CalculationAddon`

```text
vendor/calculation/
├── class-Emsfb-calculation.php            ← بوت‌استرپ addon، ثبت hookها
├── class-Emsfb-calc-parser.php            ← پارسر/ارزیاب امن فرمول (بدون eval)
├── class-Emsfb-calc-server.php            ← محاسبه مجدد سمت سرور روی submission
├── class-Emsfb-calc-formatter.php         ← قالب‌بندی عدد، ارز، locale digits
├── class-Emsfb-calc-payment-bridge.php    ← پل اختیاری به addonهای پرداخت
├── assets/
│   ├── js/calc-builder-efb.js             ← فرمول‌ساز در builder (autocomplete فیلدها)
│   ├── js/calc-engine-efb.js              ← موتور ارزیابی مشترک (همان گرامر سرور)
│   ├── js/calc-public-efb.js              ← محاسبه زنده در فرانت
│   └── css/calc-efb.css
└── tests/
    └── parser-cases.json                  ← موارد تست مشترک JS/PHP
```

**نکته معماری کلیدی:** گرامر فرمول یک بار تعریف می‌شود و دو ارزیاب هم‌رفتار دارد — `calc-engine-efb.js` برای نمایش زنده و `class-Emsfb-calc-parser.php` برای مقدار نهایی. مرجع حقیقت همیشه سرور است. **هرگز از `eval()` (در PHP یا JS) استفاده نمی‌شود؛** پارسر tokenizer + shunting-yard با whitelist توابع است.

## نقاط اتصال با افزونه اصلی

حداقل تغییرات هسته (الگوی تکراری موجود):

1. `AdnCLC` به `$addon_keys` در `Emsfb::get_addons_list_efb()` و `AdnCLC = '0'` به `get_default_settings_efb()`.
2. بلوک بارگذاری شرطی در `Emsfb::includes()` مشابه AdnSMF (admin + public).
3. بقیه از سمت addon روی hookهای موجود:
   - `efb_admin_localize_vars` → لیست فیلدهای فرم برای autocomplete فرمول‌ساز.
   - `efb_logic_prepare_submission` → بازمحاسبه سمت سرور و تزریق مقدار معتبر به `submitted_values` قبل از ذخیره/ایمیل.
   - فیلتر addon-side برای مبلغ پرداخت: addonهای پرداخت مبلغ را از ساختار فرم می‌خوانند؛ پل پرداخت مقدار فیلد محاسباتی علامت‌گذاری‌شده به‌عنوان «مبلغ نهایی» را با **بازمحاسبه سرور** جایگزین می‌کند. اگر در کد پرداخت فیلتر استانداردی وجود ندارد، افزودن یک `apply_filters('emsfb_payment_amount', $amount, $form_id, $submitted_values)` در مسیر پرداخت پیشنهاد می‌شود — تنها تغییر هسته‌ای فراتر از پیکربندی، آن هم فقط برای فاز 3.

اصل مهم: وقتی addon غیرفعال است هیچ asset یا منطقی load نشود؛ فرم‌هایی که فیلد محاسباتی دارند اما addon غیرفعال شده، فیلد را به‌صورت متن ساده readonly نشان دهند و submit عادی بماند.

## مدل داده (داخل `form_structer` — بدون تغییر schema)

فیلد محاسباتی:

```json
{
  "type": "text",
  "id_": "total_price",
  "calc": {
    "enabled": true,
    "formula": "({qty} * {unit_price}) * (1 - {discount}/100) + if({express}==1, 50000, 0)",
    "decimals": 0,
    "thousands_sep": ",",
    "prefix": "",
    "suffix": " تومان",
    "round_to": 1000,
    "min": 0,
    "max": null,
    "hidden": false,
    "is_payment_amount": false,
    "locale_digits": "auto"
  }
}
```

مقدار عددی گزینه‌ها (روی عناصر option موجود):

```json
{ "type": "radio", "id_": "express", "options": [
  { "label": "ارسال عادی", "calc_value": 0 },
  { "label": "ارسال فوری", "calc_value": 1 }
]}
```

نتیجه در submission به‌صورت فیلد عادی داخل `content` جدول `{prefix}emsfb_msg_` ذخیره می‌شود؛ **جدول جدیدی لازم نیست.**

## گرامر فرمول (نسخه 1)

- عملگرها: `+ - * / % ( )` و مقایسه `== != > >= < <=` فقط داخل `if`.
- ارجاع فیلد: `{field_id}` — مقدار عددی فیلد یا `calc_value` گزینه انتخابی؛ checkbox چندتایی = جمع مقادیر انتخاب‌شده.
- توابع فاز 1: `round(x, n)`, `ceil`, `floor`, `abs`, `min(...)`, `max(...)`, `sum(...)`, `avg(...)`, `if(cond, a, b)`.
- توابع فاز 2: `pow`, `sqrt`, `clamp(x, lo, hi)`, `roundto(x, step)`, `datediff(a, b, unit)`, `age({birthdate})` با پشتیبانی تقویم شمسی از طریق addon موجود Persian Date Picker (AdnPDP).
- ورودی با اعداد فارسی/عربی قبل از ارزیابی با زیرساخت `get_locale_script_chars_efb()` نرمال‌سازی می‌شود.
- خطاها (فیلد ناموجود، تقسیم بر صفر، پرانتز نامتوازن) در builder هنگام ذخیره validate و به کاربر نشان داده می‌شوند؛ در فرانت نتیجه خطا `—` نمایش داده می‌شود، نه NaN.

## تجربه کاربری Builder

- روی هر فیلد متنی/عددی، سوییچ «محاسباتی» در تنظیمات فیلد ظاهر می‌شود.
- فرمول‌ساز: textarea با autocomplete فیلدها (`{` تایپ شود لیست فیلدها باز شود)، دکمه‌های توابع، پیش‌نمایش زنده با مقادیر آزمایشی، و پیام خطای گرامری لحظه‌ای.
- تب «مقدار محاسباتی» روی گزینه‌های radio/checkbox/select برای وارد کردن `calc_value`.
- علامت «مبلغ پرداخت نهایی» فقط روی یک فیلد محاسباتی در هر فرم و فقط وقتی فرم payment است (فاز 3).

## فازهای اجرایی

### فاز 0 — زیرساخت (نسخه 0.1)
- کلید `AdnCLC`، بلوک بارگذاری، اسکلت `vendor/calculation/`، فعال/غیرفعال از صفحه Add-ons.

### فاز 1 — MVP (نسخه 1.0)
- پارسر مشترک JS/PHP با چهار عمل اصلی + توابع پایه + `if`.
- سوییچ «محاسباتی» + فرمول‌ساز با autocomplete + validation در builder.
- `calc_value` برای گزینه‌ها.
- محاسبه زنده فرانت + بازمحاسبه سرور + ذخیره در submission + نمایش در ایمیل/Response Viewer.
- قالب‌بندی: اعشار، هزارگان، پیشوند/پسوند، اعداد فارسی.
- تست: موارد مشترک `parser-cases.json` در PHPUnit و تست مرورگر.

### فاز 2 — توابع پیشرفته (نسخه 1.1)
- زنجیره فرمول‌ها (فرمول روی فیلد محاسباتی دیگر) با تشخیص حلقه (cycle detection).
- فیلد محاسباتی مخفی، clamp/roundto، جدول نرخ (lookup).
- توابع تاریخ/سن با پشتیبانی شمسی (اتصال اختیاری به AdnPDP).
- سازگاری تست‌شده با multi-step و Conditional Logic (فیلد مخفی‌شده توسط logic از فرمول حذف/صفر شود — رفتار قابل تنظیم).

### فاز 3 — قیمت‌گذاری پویا (نسخه 1.2)
- پرچم `is_payment_amount` و پل امن به Stripe/PayPal/PersiaPay: مبلغ نهایی همیشه بازمحاسبه سرور.
- سناریوهای تخفیف/مالیات/هزینه ارسال آماده (recipeهای مستندشده).
- Regression کامل روی فرم‌های پرداختی موجود.

### فاز 4 — رشد (نسخه 1.3+)
- ویجت خلاصه فاکتور (breakdown نمایش اقلام محاسبه).
- خروجی نتیجه به webhook (AdnWHS) و Google Sheets (AdnGoS).
- قالب‌های آماده: وام، BMI، برآورد قیمت، هزینه ارسال.

## تست و پذیرش

- Unit دو-زبانه: هر case در `parser-cases.json` باید در PHP و JS نتیجه یکسان بدهد (جلوگیری از واگرایی کلاینت/سرور).
- تست امنیتی: تزریق رشته در فرمول (XSS)، تلاش برای eval، ارسال مقدار محاسباتی جعلی از کلاینت (باید سرور جایگزین کند)، دستکاری مبلغ پرداخت.
- تست locale: ورودی اعداد فارسی/عربی، جداکننده اعشار locale، RTL.
- تست سازگاری: multi-step، Conditional Logic فعال/غیرفعال، افزونه‌های کش، Gutenberg/Elementor/WPBakery.
- Regression: فرم‌های بدون فیلد محاسباتی با addon فعال هیچ asset اضافه و تغییر رفتاری نداشته باشند.

# T02 — گزارش خطا با توضیح و اقدام روشن

وضعیت: آمادهٔ اجرا. وابستگی: ندارد. [قیود مشترک](README.fa.md).

فایل‌ها: `includes/class-Emsfb-request-health.php`، `public/assets/js/request-health-efb.js`، متن‌های ترجمه در `includes/functions.php`، تست‌های `test-request-health.php/js`.

## خروجی

به‌جای نمایش اصلی کدهای خام، هر گروه خطا عنوان، زمان آخرین مشاهده، تعداد رخداد و یک اقدام مرتبط داشته باشد؛ جزئیات HTTP/source/reason بازشونده و برای مدیر مجاز باشد.

نمونه‌ها: «مشکلی هنگام ارسال فرم مشاهده شد»، «سرور درخواست را رد کرده است؛ علت هنوز مشخص نیست»، «نتیجهٔ ذخیره هنوز مشخص نیست؛ پیش از ارسال مجدد، ثبت‌ها را بررسی کنید».

## اجرا در دو بخش

A: نگاشت allowlist reason/operation به عنوان و راهنما، بدون تغییر ذخیره یا ارسال گزارش. B: نمایش دسترس‌پذیر و کم‌ازدحام؛ رخدادهای تکراری تجمیع شوند. اگر دادهٔ کافی برای بازیابی‌شده/حل‌نشده نداریم، وضعیت حل‌شدن جعل نشود؛ نیاز به قرارداد جدید جدا ثبت شود.

## پذیرش

403 به افزونهٔ خاص نسبت داده نشود؛ شمارش رخداد با تعداد ثبت ازدست‌رفته برابر معرفی نشود. گزارش مرورگر ناشناس همچنان تأییدنشده باشد. مجوز manage_options، escape خروجی، محدودیت ذخیره و نرخ حفظ شوند. فقط مدیر گزارش را ببیند؛ هیچ دادهٔ فرم یا توکن اضافه نشود. تست نگاشت حالت‌های nonce، 403، 429، 500، pending و reason ناشناخته انجام شود.

تحویل: هنوز تغییری ندارد. اقدام بعدی: خواندن notice و allowlist فعلی و طراحی نگاشت همان حالت‌ها.

What is conditional logic in Easy Form Builder?

Quick answer: Conditional logic is a rule engine that changes a form’s behavior in real time. Each rule has a condition (IF) and an action (THEN). When the condition is true, the action runs — showing a field, skipping a step, sending an email, redirecting the visitor, or firing a webhook.

A traditional WordPress form is static: every visitor sees the same fields in the same order and triggers the same email. That is fine for a basic contact form, but it breaks down the moment your form has to serve more than one audience. A sales inquiry, a support ticket, and a job application all need different questions, different recipients, and different follow-ups — yet forcing every visitor through one long, generic form leads to abandoned submissions and messy data.

The Conditional Logic addon solves this by letting the form adapt to the person filling it out. Instead of building five separate forms, you build one intelligent form that reveals the right questions, routes to the right team, and confirms with the right message — automatically. It reads signals such as the visitor’s answers, values in the URL, whether they are logged in and their WordPress role, the current step of a multi-step form, and the outcome of a payment, then applies your rules to decide what happens next.

The anatomy of a rule

IF (condition)
Customer Type is Business
→
THEN (action)
Show “Company Name” + Set required

Read it as a sentence: “If the customer type is Business, then show the Company Name field and make it required.” That is the entire mental model — everything else is more conditions and more actions.

How to activate the Conditional Logic addon

These steps follow the current structure of the plugin. The addon’s internal name is AdnSMF, but you will see it labeled Conditional Logic Addon in the admin.

1

Confirm Easy Form Builder is active

In the WordPress dashboard, open Plugins and make sure Easy Form Builder is active. Then open the Easy Form Builder menu from the admin sidebar.

2

Open the Add-ons page

In the Easy Form Builder submenu, click Add-ons. Locate the Conditional Logic Addon card — it is marked with a diagram icon and a “smart form” description.

3

Install or activate the addon

If it is not installed, download or install it. If it is installed but inactive, activate it. If the card is locked or shows an upgrade prompt, your current package does not yet include full access — upgrade your plan to unlock it.

4

Create or open a form

Go to the Create page to build a new form, or edit an existing form from the Panel. Add the fields your rules will read (the conditions) and the fields your rules will change (the targets) before you start.

5

Open Form Settings → Conditional Logic

Inside the form builder, open Form Settings and click Conditional Logic. If the addon is active and your plan allows it, the Rule Builder opens. On a Free plan you will see the upgrade panel instead of the editor.

6

Build a rule and verify with Test Mode

In the Fields tab, click Add, name the rule, choose the IF condition, build the THEN action, and Save. Before publishing, run Test Mode to confirm the rule shows as Matched, Not matched, or Skipped as expected.

Troubleshooting tip: If you cannot see the Conditional Logic button, check the Add-ons page first. If the button appears but the editor will not open, verify your plan level, that the addon is active, and that the form actually contains fields the rules can target.

Tutorial: show a field only for business customers

This is the single most common thing people search for — how do I show a field based on the visitor’s answer? Here is the complete walkthrough.

Step A — Prepare the fields

  1. Add a choice field named Customer Type.
  2. Give it two options: Personal and Business.
  3. Add the Company Name and VAT Number fields.
  4. If the form is multi-step, prepare the “Company details” step too.

Step B — Build the rule

  1. Open the Fields tab and click Add.
  2. In IF, choose the Customer Type field.
  3. Set the operator to is and pick the value Business.
  4. In THEN, add Show Field → Company Name.
  5. Add a second action: Set Required → Company Name.
  6. Save, then Test Mode with both values.

Now the Company Name field stays hidden for personal customers and only appears — already marked as required — when someone selects Business. Because hidden fields are skipped during validation, a personal customer is never blocked by a required field they never saw.

The four rule tabs, explained

Rules are organized into four tabs by what they control. You never edit code — each tab is a set of cards, dropdowns, and a Test Mode button.

Fields

Show, hide, require, make optional, enable, disable, set or clear values, and control multi-step navigation.

Notifications

Send conditional emails to the right team — sales, support, billing, or a specific recipient — with dynamic subjects.

Confirmation

Show a different thank-you message, change its title, color, and icon, or redirect the visitor after submission.

Webhook

Fire or stop a webhook based on answers, payment, or request type, and control which fields are sent in the payload.

Best practices for maintainable rules

A handful of habits keeps your conditional forms readable, testable, and easy to hand over.

Map the paths first

Before building anything, list the main journeys: personal vs business, sales vs support, paid vs unpaid.

Name rules clearly

“Show company fields for business users” beats “Rule 1” when you return six months later.

Test every path

One Test Mode run isn’t enough. Exercise each main path with realistic values before publishing.

Use priority for conflicts

If several rules touch one field, set Priority and “Stop after this rule matches” to avoid clashes.

Don’t fear hidden fields

Hidden fields and steps are ignored in validation, so required rules on them never trap the visitor.

Keep conditions minimal

Prefer a few clear rules over one giant nested group. Simpler logic is easier to test and debug.

Troubleshooting common issues

I don’t see the Conditional Logic button

Open the Add-ons page and confirm the Conditional Logic Addon is installed and active. On a Free plan the editor is replaced by an upgrade panel.

The button is there but the editor won’t open

Check your plan level, verify the addon is active, and make sure the form contains fields the rules can target — an empty form has nothing to build rules on.

A rule isn’t firing

Run Test Mode and read the status: Matched, Not matched, or Skipped. A mismatched operator or value is the most common cause. Check rule Priority if two rules affect the same field.

A required field blocks submission unexpectedly

Confirm the field is actually hidden by a rule on that path. Hidden fields are skipped in validation; a field that is only disabled (not hidden) may still validate.

Frequently asked questions

What exactly does Conditional Logic do?

It changes the form based on answers, field values, URL parameters, user status, current step, and payment. The result can be showing or hiding a field, requiring a field, sending an email, displaying a thank-you message, redirecting, or firing a webhook.

Do I need to know how to code?

No. Every rule is built visually in an IF/THEN interface. You choose the field, operator, value, and action — no PHP, JavaScript, or CSS.

Why can’t I see Conditional Logic after activating it?

First check the Add-ons page and make sure the addon is active. Then open a form and go to Form Settings. On a Free plan, or if the addon is inactive, you may see an upgrade or lock panel instead of the rule builder.

Will a hidden required field block submission?

No. In the current addon logic, any field or step hidden by a rule is ignored during validation and submission, so a visitor is never stopped by a required field they cannot see on their path.

What can I do with multi-step forms?

You can show a step, hide a step, or jump the visitor directly to a specific step. This is ideal for registration, quote, support, and payment flows.

Can emails go to different people based on the answer?

Yes. In the Notifications tab you build conditional rules that set the recipient, subject, and template — e.g. Sales to the sales team, Billing to finance, and Technical to support.

Can I redirect the visitor to a different page after submitting?

Yes. In the Confirmation tab you can show a conditional message or redirect to a specific URL, and you can inject field tokens into the destination URL.

What is Test Mode for?

Before publishing, you enter sample values and see which rules are Matched, Not matched, or Skipped. It catches mistakes in complex paths before real submissions arrive.
